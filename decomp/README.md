# AttT decomp — декомпиляция движка «Восхождения на Трон» и «Валькирии»

Цель — получить исходный код движка, который собирается в рабочий `ATThrone.exe`, чтобы модернизировать
игру и упростить её модификацию. Работа идёт постепенно: на каждом шаге собранный exe — это **оригинальный
код плюс уже декомпилированные функции**, поэтому игра работает всё время, а каждую переписанную функцию можно
проверить в игре отдельно.

В репозитории нет ни байта игры: все инструменты берут `ATThrone.exe` пользователя на входе.

## Что здесь есть

| Каталог | Содержимое |
|---|---|
| `tools/` | анализ exe (RTTI, Lua-биндинги, соглашения вызова, сопоставление AttT ↔ Валькирия), перевод exe в объектный файл (`exe2obj.py`) и проверка пересборки, сценарий полного анализа `analyze.sh` |
| `ghidra/` | скрипты Ghidra 11.x: недостающие функции, регистровые параметры LTCG, имена, `__thiscall`, структуры классов, выгрузка декомпиляции |
| `symbols/` | имена и адреса: `attt.sym`, `valk.sym` (сгенерированы), `attt_manual.sym` (ручные — правьте этот), конструкторы, таблицы функций (регистровые входы, `ret N`, портящиеся регистры), карты функций и данных AttT → Валькирия |
| `rebuild/` | сборка exe из оригинала и декомпилированного кода: `build.py`, заголовки (`decomp.h`, совместимый с VC2005 `std::string`), исходники в `rebuild/src` |

## Исполняемые файлы

| | AttT (Steam 1.1.128) | Валькирия (рус., Steam) |
|---|---|---|
| TimeDateStamp | 475EABAF (2007-12-11) | 4883FB4F (2008-07-21) |
| Компилятор | MSVC 2005 (VC8), /O2, **/LTCG** | MSVC 2005 |
| `.text` | 2,1 МБ | 3,3 МБ (+ zlib 1.2.1, Ogg Vorbis, свой стриминг звука) |
| Функций | 18 591 (из них 6 801 — SEH-фанклеты `Unwind@`) | 20 884 |
| RTTI | 569 классов, 704 vtable | 571 класс, 706 vtable |
| Перемещения (.reloc) | полные, 89 171 | полные, 102 051 |

Главная находка: в обоих exe **полная таблица перемещений**, поэтому каждый абсолютный адрес известен, и exe
можно разобрать в перемещаемый объектный файл и собрать заново компоновщиком вместе с новым кодом
(`tools/exe2obj.py`). Проверено: пересобранные без изменений exe совпадают с оригиналами (все байты и все 89–102
тысячи указателей), а под Wine оригинал и пересборка обеих игр ведут себя одинаково (лог ошибок, `graphic.cfg`,
одно и то же место остановки без игровых ресурсов).

Особенность AttT: сборка с **/LTCG** — внутренние функции получают параметры в произвольных регистрах
(`luaL_checknumber` принимает `L` в EAX) и вызывающий код иногда рассчитывает, что вызываемая функция не трогает
ECX/EDX. Инструменты это учитывают: `regparams.py` находит регистровые входы по машинному коду, `regclobber.py` —
какие регистры функция портит (транзитивно), а сборка генерирует переходники. Валькирия собрана без этого
(та же функция Lua получает `L` на стеке), и один и тот же исходник собирается для обеих игр.

## Как собрать exe с декомпилированным кодом

Нужны `clang`, `lld-link`, `llvm-dlltool`, `llvm-nm`, `llvm-undname` (LLVM 15+), Python 3 с `pefile` и `capstone`.

```
python3 decomp/rebuild/build.py --exe "C:/Games/Ascension to the Throne/ATThrone.exe" --out build/ATThrone.exe
```

Игра определяется по TimeDateStamp. Результат кладётся вместо `ATThrone.exe` (оригинал сохраните).
`--laa` сразу ставит флаг Large Address Aware. В конце печатается проверка: все байты оригинала, кроме
заменённых функций, на месте.

### Как пишется декомпилированный код

```c
#include "decomp.h"

ORIG_FN(00401680, lua_Number, (lua_State *L /* EAX */, int narg));   // оригинальная функция, нужна новому коду

DECOMP(004064D0)                       // заменяет оригинал по этому адресу (адрес AttT)
int math_abs(lua_State *L)
{
    lua_Number x = ORIG_CALL(00401680)(L, 1);
    ...
}
```

* `DECOMP(адрес)` перед определением — функция заменяет оригинал: в старое начало ставится переход, все
  указатели на неё (vtable, таблицы Lua) перенаправляются. Если у оригинала регистровое соглашение LTCG или он
  сохранял регистры, на которые рассчитывают вызывающие, сборка сама генерирует переходник. Методы классов
  пишутся как обычные методы C++ (`__thiscall`).
* `ORIG_FN / ORIG_THISCALL / ORIG_FASTCALL / ORIG_STDCALL` — объявление оригинальной функции (`sub_XXXXXXXX`).
  Для регистровых соглашений LTCG сначала перечисляются регистровые параметры (ECX, EAX, EDX, EBX, ESI, EDI),
  сборка сделает cdecl-обёртку.
* `ORIG_VAR(адрес, тип)` — глобальная переменная оригинала.
* Адреса всегда от AttT; для Валькирии `build.py` переводит их по `symbols/attt2valk.tsv` и
  `symbols/attt2valk_data.tsv` (сопоставлено 13 964 функции и 7 281 адрес данных; сверено с картой AttTFix — без
  расхождений).
* `std::string` — `rebuild/include/msvc8/string.h`: та же раскладка (28 байт), методы из `MSVCP80.dll`, как у игры.
* Код компилируется clang под ABI MSVC (`i686-pc-windows-msvc`), т. е. классы, vtable и `__thiscall` совместимы
  с оригиналом.

## Полный анализ заново

```
GHIDRA=/opt/ghidra_11.4.2_PUBLIC WORK=/tmp/attt-work LUA_SRC=/path/lua-5.1.2/src \
  decomp/tools/analyze.sh ATThrone_AttT.exe ATThrone_Valkyrie.exe
```

Около часа на 4 ядрах. Результат: проекты Ghidra с именами, регистровыми соглашениями и структурами классов
(`$WORK/proj`, открываются в Ghidra 11/12) и сырая декомпиляция, разложенная по классам и исходным файлам
(`$WORK/decomp/<игра>/*.cpp`, `INDEX.tsv`). Сырая декомпиляция — справочник для переписывания: она не
компилируется как есть.

### Откуда берутся имена

1. **RTTI** — все 569 классов с иерархией, vtable, виртуальные функции (`Класс::vfN`, владелец слота — самый
   базовый класс, где функция встречается), деструкторы (`scalar deleting destructor` → `~Класс`), конструкторы
   (запись vtable + вызов после `operator new`, заодно размеры 166 классов).
2. **Слоты** — имя слота в базовом классе переходит на все переопределения: `SLOT CUpdateObject 1 Update` в
   `attt_manual.sym` даёт `Update` 107 классам.
3. **Lua** — таблицы методов Lunar (193 метода), глобальные функции (`lua_pushcclosure` + `lua_setfield`), таблицы
   `luaL_Reg` стандартных библиотек; функции Lua 5.1.2 опознаются по исходникам (`libmatch.py`).
4. **Экспорты** exe (13 имён с полными сигнатурами), **строки ассертов** (`.\Engine.cpp` и т. п. — файл).
5. **Ручные имена** из исследования AttTFix (`symbols/attt_manual.sym`).
6. Всё переносится на Валькирию через сопоставление функций (`crossmatch.py`: vtable одинаковых классов,
   таблицы Lua, маскированные байты, строки, граф вызовов, порядок в коде).

## Состояние и дальнейшая работа

Готово: инструменты и конвейер анализа, имена (≈3 300 на игру), регистровые соглашения, структуры классов,
сырая декомпиляция всех функций, пересборка exe с заменой функций для обеих игр.

Декомпилированный и подключённый к сборке код — `rebuild/src` (см. список там). Дальше — переписывать подсистемы
по одной, проверяя каждую в игре: ядро движка (окно, главный цикл, устройство D3D9, кадр, настройки), файловая
система паков, Lua 5.1 (заменить целиком исходниками 5.1.2 с `LUA_NUMBER=float`), звук, GUI, мир, бой.
Когда весь код игры будет переписан, оригинальный exe перестанет быть нужен для сборки.
